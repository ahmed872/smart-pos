# توقيع برنامج التثبيت على Windows (Code Signing)

## الوضع الحالي
برنامج التثبيت يُنشر حاليًا **بدون توقيع رقمي**، لذلك يعرض Windows SmartScreen تحذيرًا عند التثبيت. مسار البناء في `.github/workflows/build-release.yml` جاهز للتوقيع، ويبدأ التوقيع تلقائيًا بمجرد إضافة شهادة في GitHub Secrets، بدون أي تعديل في الكود.

لا توجد أي شهادة أو كلمة مرور داخل المستودع، ويجب ألا تُضاف إليه أبدًا.

## ما يلزم تجاريًا
شهادة **Code Signing** صادرة لاسم الشركة من جهة إصدار معتمدة:

| النوع | الأثر على SmartScreen | ملاحظات |
|---|---|---|
| OV (Organization Validation) | يختفي التحذير تدريجيًا بعد أن تكتسب الشهادة سمعة | الأرخص |
| EV (Extended Validation) | لم تعد تمنح سمعة فورية منذ 2024، فأثرها مماثل لـ OV تقريبًا | أغلى |
| Azure Trusted Signing | خدمة سحابية من Microsoft، ويشترط توثيق هوية الشركة | اشتراك شهري منخفض التكلفة |

منذ يونيو 2023 تُلزم معايير CA/Browser Forum بحفظ مفتاح الشهادة على جهاز آمن (HSM أو Token)، ولذلك لم تعد جهات الإصدار تسلّم ملف `.pfx` قابلًا للتصدير في الشهادات الجديدة. الاختيار العملي:

1. **شهادة على خدمة توقيع سحابية** (DigiCert KeyLocker، أو SSL.com eSigner، أو Azure Trusted Signing): تُضاف خطوة توقيع خاصة بالمزوّد بعد البناء، أو يُضبط `win.sign` في electron-builder على أداة المزوّد.
2. **شهادة `.pfx` قابلة للتصدير** (شهادة قديمة، أو داخلية للمؤسسة): تعمل مباشرة بالإعداد الحالي، كما في الخطوات التالية.

## التفعيل بشهادة `.pfx`
1. حوّل الشهادة إلى Base64 على جهاز آمن:
   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes('certificate.pfx')) | Set-Clipboard
   ```
2. في GitHub افتح: **Settings → Secrets and variables → Actions → New repository secret**، ثم أضف:
   - `WIN_CSC_LINK`: نص Base64 الناتج.
   - `WIN_CSC_KEY_PASSWORD`: كلمة مرور الشهادة.
3. (اختياري) أضف المتغير `REQUIRE_CODE_SIGNING` بالقيمة `true` في تبويب **Variables**، ليرفض workflow الإصدار أي نسخة غير موقّعة.

## ما يحدث أثناء البناء
- تُمرَّر الأسرار إلى خطوة البناء الموقّع فقط، ولا تُكتب في أي ملف أو سجل.
- يوقّع electron-builder البرنامج (`Cashier System.exe`) وبرنامج إلغاء التثبيت وبرنامج التثبيت، بخوارزمية SHA-256 وختم زمني.
- تتحقق خطوة **Check code signature** من حالة التوقيع عبر `Get-AuthenticodeSignature`. إذا كانت الشهادة مضبوطة وكان أي ملف بدون توقيع صالح، يفشل الإصدار.
- الـfuses تُضبط قبل التوقيع (في `afterPack`)، فلا يُعدَّل الملف بعد توقيعه.
